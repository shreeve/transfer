# Handoff

How the code works now, why it is built this way, and the traps that already cost a day. `docs/SPEC.md` is what the product does; `AGENTS.md` is the rule list; `docs/RELEASING.md` is releases and updates. The package builds on Apple-silicon macOS 27 with the Xcode 27 toolchain with no warnings, and `swift test` passes.

## The seam

Two protocols in `TransferCore` are the seam (`RemoteSession.swift`). `SessionProvider` is the library: saved servers, one `RemoteSession` per server, the config, and `transfer(_:progress:)`, which runs every paste and drop. `RemoteSession` is one server. `TransferHub` and `SSHConnection` in TransferIO implement them. Every window and tab has its own `TransferModel`, which asks the hub for sessions, so windows share one login per saved server. The model holds the server it shows as one `ServerContext`, made when a connect starts and installed whole once the login works; work for a server counts only while its context is installed, so a slow listing or a late login never lands in a window that has moved on. Work the user starts takes the context before its first await and keeps it: a star, a paste, or a navigation acts on the server it began on, and Upload…, Download Copy…, or a paste between servers whose window has moved on meanwhile does nothing and says so. A window that closes calls `close()` on its model, which stops its listings, its login, and its sheets at once; its queued transfers run on.

The library root is `~/Library/Application Support/Transfer`, or the folder `TRANSFER_LIBRARY` names (`LibraryOverride`). Under it: `transfer.sqlite`, `config.json`, `Live/`, `ssh/` (control sockets), and per-login scratch. One copy of Transfer holds a library at a time: the hub takes an exclusive `flock` on `transfer.lock` for its life, and a second copy is refused, since the launch sweeps, the temps, and the control sockets all assume no other process is using the library. Caches go to `~/Library/Caches/Transfer` (previews) and `~/Library/Caches/com.github.shreeve.transfer` (the clipboard's staging), or both to `Caches/` under a custom root, so tests and development builds never touch the user's.

## The SSH session

`SSHConnection.swift` is login, host keys, askpass, and channels; `SSHConnection+Transfers.swift` is the transfer engine; `Subprocess.swift` runs every helper process.

- **Login** is single-flight: a `connect` while one is in flight joins it, but a login already stopping is waited out and a fresh one starts. A login stops when the last caller waiting for it leaves, or when any of its questions is answered with Cancel, and its questions go to the caller that joined last and still waits (`LoginPrompts`). The master is `ssh -N` with `ControlMaster=yes`, `ControlPersist=no`, `ForkAfterAuthentication=no`, `Compression=no`, `ServerAliveInterval=15` and `ServerAliveCountMax=3` (a dead network is noticed in about 45 s), and `StrictHostKeyChecking=yes`. Every ssh that joins or runs on the server also passes `RemoteCommand=none`, `RequestTTY=no`, `ClearAllForwardings=yes`, and `PermitLocalCommand=no`, since `~/.ssh/config` may set any of them for the user's own logins, and a `ControlPersist` would fork the master away where the app cannot stop it. One five-minute limit covers the whole login, prompts included. A login dropped before authentication (sshd's `MaxStartups` or `PerSourcePenalties`) is tried twice more. Everything a login starts is released together, and a new login waits until the previous master has exited, so an old master never unlinks a socket a new one has bound. A session that replaces another for the same server (its settings changed) starts the old one's disconnect and its first login waits for it (`init(replacing:)`), since ssh removes the control socket by name.
- **Host keys:** ssh checks the key itself, against the user's own files, so a known host costs one connection. Only when ssh refuses the key (`HostKeyFailure` reads its stderr) does a probe learn the offered key: a no-auth `ssh … true` into a temporary known-hosts file under `hostkey-*`, which honors `~/.ssh/config`, aliases, and `ProxyJump`. The user sees First Seen or Changed, as ssh judged it, and the master starts once more, so a first contact is three connections. Always Trust and Replace write only the first user file `ssh -G` names, hashed when `HashKnownHosts` is on, in one `O_APPEND` write; Replace first removes the old lines with `ssh-keygen -R`. Trust Once hands the master the probe's file until disconnect. Cancel on a first-seen key ends the login as `.cancelled`; declining a changed key is `hostKeyRejected`, as is a `@revoked` key, which is refused without a question. When `ssh -G` failed, Always Trust and Replace fail with an error rather than trust for one login; a config whose known-hosts file is `/dev/null` gets trust for this login only, with a notice.
- **Askpass:** each login gets an `ask-*` folder under the library root with a helper script; ssh runs it for each prompt, and the model shows a sheet. The helper gives up with the login or as soon as its folder is removed, and lets go of ssh's stderr at once; `Subprocess` waits at most a second for a process's pipes after it exits, so a Cancel during the host-key probe ends the login at once. A password and a key passphrase are separate Keychain items (`KeychainStore.Kind`), so a passphrase is never sent as a password; each answers only this server's own prompt of its kind, never a `ProxyJump` host's, and only once per login. Disconnect and every failed login remove the login's `ask-*` and `hostkey-*`; the hub removes every `ask-*`, `hostkey-*`, and 0.1.7's `key-*` when it starts, holding the library lock, so none belongs to a login in progress.
- **Channels:** SFTP is spoken by this app on passengers, `ssh -S sock -s -- <host> sftp` with `ControlMaster=no`, `BatchMode=yes`, and `ProxyCommand=/usr/bin/false`, so a passenger whose master is gone or refuses it fails at once instead of logging in on its own with the default port and keys. Browse, interactive, and walker open at login; a reserved one that dies is reopened when next needed, at most once every 5 s. Data channels open on demand, at most seven (`SSHConnection.dataChannels`: three reserved plus seven is sshd's default `MaxSessions` of 10), and after the server refuses one, no other opens for 10 s. A channel gives up when SFTP has not started within 15 s (a shell startup file that prints text fails at once with a clear error), and when a server has answered nothing for 60 s while requests wait; `copy-data`, which answers only when the whole file is written, is exempt. When the master dies, every waiter gets a lost connection, which transfers retry, and the window hears `.disconnected`.
- **The data pool** shares channels (`SSHConnection.DataShare`): a file of at most 256 KB takes a sixteenth of one, a larger file or one of unknown size takes it whole. A caller takes an idle channel, else opens one while fewer than seven are open or opening, else the least loaded with room; waiters are served in order, so a large file first in line is not passed by small ones, nor by a newcomer opening a channel after a refusal's backoff. Sixteen per channel keeps at most 112 files open on the Mac and 32 handles on each `sftp-server`.
- **The interactive lane** (`InteractiveLane`) runs the file the user is waiting on, one job at a time. Kinds: `.preview` (Quick Look, inspector, prefetch), `.view` (a file opened to view), `.open` (a Live download), `.save` (a Live upload). Opens, views, and saves run in order and are never interrupted; previews wait behind them, and only a newer preview replaces a preview.
- **Listing** keeps four `READDIR` requests in flight, sixteen once a folder has filled four pages, and streams pages. `SFTPChannel.readDirectory` drops every name that is not exactly one path component, and `SFTPWire` refuses a frame of length zero or over OpenSSH's own limit, and checks every field's length against its packet.
- **Renames** the user asks for never replace: `SFTPChannel.rename` looks the destination up first, then uses plain RENAME (which on OpenSSH would still replace an empty folder); a change of case alone within one folder uses `posix-rename`, after the folder's listing shows no second file. `SFTPChannel.replace` is the temp-and-rename that does replace: with `posix-rename@openssh.com` it is atomic; without it the old file steps aside under a hidden name (`.transfer-old-<uuid>`) and comes back if the new one cannot take its place. The aside is recorded with the temps (`AsideLog`) until it is back or removed, so after a dropped connection the next login puts it back, or removes it when the new file took its place.
- Open in Terminal (`terminalCommand`) joins the master when it is up, else logs in with the same port and identity, and is never a master on Transfer's socket.

## Transfers

- **Files:** every direction writes a hidden temp beside the final name (`.<name>.transfer-<uuid>`, the name cut on a character boundary so the temp fits 255 bytes: `CopyRules.tempName`, sharing `LiveDecision.siblingName`) and renames it into place. Temps on both sides are recorded in SQLite before the first byte and forgotten only once removed: one that could not be removed goes at the next login (on the server) or the next launch (on the Mac). A download takes the server's permissions without setuid, setgid, or sticky bits and is quarantined as a browser's download is; a Live working copy is not quarantined. Each data channel keeps 2 MB in flight, 32 requests of 64 KB. A short READ reply is not the end of the file: `ReadPlan` asks again for the rest (a file with no listed size reads through it until EOF), only EOF ends a download early, and a download that would leave a gap fails. A download reads only up to the listed size, so every channel checks the file it opened against the listing: the owning channel sends FSTAT with its first READs and, before writing a byte, fails a mismatch with `changedOnServer`, which retries like a dropped connection, so a file that grew is never placed cut short. A channel sends a file's requests without waiting where the server's in-order handling allows: an upload's writes, FSETSTAT (mode and time), and CLOSE go out together, as do a server copy's two OPENs and then its `copy-data`, FSETSTAT, and CLOSEs; the rename waits until every write and the close are acknowledged. A file of 8 MB or more also takes up to three more channels that are idle or can open then (`withSpareData`, never ahead of a waiting caller): each opens the file itself and takes 64 KB pieces from one `DownloadParts` or `UploadParts`; a helping download channel checks FSTAT first and steps aside on a mismatch; any piece failing fails the file and removes its temp.
- **Placement:** every name from a server that reaches the Mac goes through `LocalPlacement`, and what already holds a name is settled by `Placement.settle`, the same in every direction: nothing there writes, a folder merges into a folder, the same file (size and whole-second time) or the same link is skipped, a folder never replaces a file or the reverse, and anything else asks through `OperationPrompts.current`, the operation's own prompt, set by the model's operation runner. With nobody to ask the operation fails. A Replace removes only what the user was asked about: the name is looked up again just before, and anything else there now fails the item; a link made where nothing was is made at the name itself, so it never replaces what took the name since. A folder copy walks on the walker and hands file bodies to the pool as names arrive, lists a destination folder once instead of looking up each name, keeps at most `CopyTally.jobLimit` (224) file jobs in flight, copies links as links, skips sockets, FIFOs, and devices, and goes on past an item that fails, naming every failure at the end.
- **Pastes and moves** (`TransferEngine`, behind `SessionProvider.transfer`): on one server, a copy on the server (`copy-data`, else through the Mac), or a rename per item when moving; pasting into the items' own folder makes `name copy`. Between servers, each item goes down into `$TMPDIR/Transfer-<uuid>` and up again; an item holding two names the Mac's disk cannot tell apart is refused before anything is copied. From this Mac, uploads. A move snapshots the destination per item, just before that item's copy first reaches it, copies, walks the original again, and removes it only when `MoveCheck` finds this item wrote a complete copy keyed by exact name bytes: nothing the destination held before counts, an earlier item's copy of the same name included, unless the user chose Replace, and in a move a lookalike is asked about, never skipped. Between servers the removal takes only the verified entries still as they were, and a folder only once it is empty; what changed or was added since stays, and the item is reported as changed during the move (`TransferKept.Reason.changed`). A Live save under the original after the walk (`LiveSync.saveMark`) keeps all of it. Finder originals go to the Trash whole, which keeps anything added since where the user can find it. A move between saved servers or from the Mac first makes a uniquely named folder at the destination and looks for it beside the originals, so two routes to one disk never copy an item onto itself. A Live file with unsynced edits keeps its original. Every item gets its turn: one that fails is collected with the kept originals, and all are reported together once the rest are done (`TransferKept`); only a cancel, a dropped connection, or a timeout ends the paste at once. The request's memo, kept per item, holds what each attempt finished, the names Keep Both chose, and what each item wrote, so a retry does none of it twice and no item counts another's copy as its own.
- **Previews:** the cache lives in `Preview/` under the cache root, capped at 1 GB by last use and excluded from backup. A file keeps its remote name (Quick Look's Open With and a viewing app show it) inside a folder named for the SHA-256 of the server's id, the path's bytes, and, for a partial copy, the file's size and time, so two servers never share an entry and an unchanged file reuses its copy; eviction takes whole folders. The inspector fetches only the first 64 KB of a text file (`EditableFile.previewHead`); Quick Look renders the first 512 KB of one as highlighted HTML; everything else is fetched whole and reused while its size and time match. The inspector previews other files only up to 8 MB, and prefetches the neighbors of each preview one at a time.

## The clipboard

`Clipboard.shared` (`Clipboard.swift`) is one per app and mirrors the general pasteboard. Command-C writes the remote paths (`remoteDragType`, `com.github.shreeve.transfer.remote-items`, plus the paths as text), counts the tree on the walker, and downloads the items to a staging folder so Finder can paste them, adding the file URLs when the download is complete: Finder reads only file URLs from the clipboard. Copies over 1 GB, trees that could not be counted in full, and trees holding two names the Mac's disk cannot tell apart are not staged. Clips stage under `Staging/` in the cache root, which a launch empties: only one copy of Transfer runs on a library, and each library has its own cache root. A replaced clip's folder is removed ten minutes later, since Finder may still be pasting from it; quitting removes `Staging/`. Escape on a clip from Finder hides the bar and leaves the pasteboard alone. Paste and drop (`PasteActions.swift`) only queue a `TransferRequest`.

## Live files

Live files are one component, `LiveSync` (`LiveSync.swift`), owned by the hub: the records and their `live_files` rows (dirty, paused, the conflict and what the server held, the working copy's exact stamp and SHA-256 at the last sync), one FSEvents stream over the Live folder (`LiveWatcher`), and one worker per server. Every pass and every command for a server's files (open, conflict choices, discard, and a rename or delete under a Live path) runs on that worker in turn, so nothing races and nothing is locked; Pause's flag is the one write from outside. A rename or delete also waits for a Live open under that path still queued or downloading. A removal above a Live file with unsynced bytes refuses with `liveUnsynced` unless forced, and a forced one discards the Live files only after the server's delete succeeds. Delete forces an item only when every unsynced Live file under it is one its sheet named (`deleteSelection(warned:)`); an item holding one the sheet did not name is refused, and the sheet comes back naming it. Remove Server's check, the close, and the removal of `Live/<id>` happen in one actor turn (`closeIfSynced`), after a last count that reads no bytes, so no save lands between them. `LiveDecision.isUnsynced` is the one test for "holds bytes the server lacks", counting an edit no pass has seen yet; Discard, Remove Server, Delete's warning, and Quit all use it.

A rename changes only the remote path: the working copy keeps its old local name, because an editor holding it open keeps saving there and the watcher knows the copy only by that name. A pass acts only on a working copy that has held still for 350 ms, then asks `LiveDecision` what to do, feeding it a digest when the stamp moved and the server's file when the copy changed: a touched-only copy is restamped, not uploaded; a watcher event that finds the stamp unmoved is an echo and does nothing; a missing copy gets a second look a second later; an unreachable server parks the pass until login; other failures retry at 1, 2, and 4 s. An upload requires the stamp the pass saw hold still, reads through `NSFileCoordinator`, goes on the interactive lane, and checks just before the rename that the server still holds the base (or this save's own bytes); the new base is our own temp's fingerprint. A server file with the edit's size and time is adopted as synced only when it is our own unconfirmed upload. The temp takes the server file's permissions, never the working copy's private 0600. A conflict writes the `(server)` copy first, then sets the flag and sends the event; that name, and the refresh download's, are cut to fit 255 bytes (`LiveDecision.siblingName`). Keep Local and Keep Both first wait until the working copy has held still for 350 ms and refuse while it is still being written; Keep Local expects the server file seen when the conflict was raised. Keep Remote on a file that has left the server since raises the conflict again as removed, keeping both copies; the record goes only when the conflict answered already showed no file (`LiveDecision.keepRemoteForgets`) or Keep Both uploaded the copy first. Server bytes replace a working copy only through one helper: downloaded beside it, measured there, and renamed over it in a coordinated write, only if the copy still has the expected stamp, so an editor's save is never overwritten. An untouched copy is refreshed only when the user opens it again. If FSEvents cannot watch the Live folder, every copy is stamped every 2 s and the user is told. A synced copy idle for a day is forgotten at launch. `SSHConnection` is the `LiveServer` (look up, fetch, save with an expectation, list names, emit). Compare opens `opendiff`.

## The library

`Store` (`Store.swift`) keeps `transfer.sqlite`: saved servers, stars (table `pins`), Live records, and remote temps. `PRAGMA user_version` is the schema version, and opening migrates one step per transaction, re-reading the version under the lock: 1 is the schema of 0.1.0 to 0.1.7, which kept no version; 2 drops the write-only `recents` table; 3 marks the move to exact-byte paths and changes no row. A path is stored as text when its bytes are UTF-8 without a NUL, as every older Transfer wrote it, and as a blob otherwise (`StoredPath`); reads and matches compare `CAST(path AS BLOB)`, so either class is the same path. After a downgrade 0.1.7 still opens the library, and its text matches (Unstar, temp cleanup) find every row it could have written. A library newer than the build is refused, untouched, and the app says why and quits. The file is in WAL mode (hence `transfer.sqlite-wal` and `-shm` beside it) with `synchronous = FULL`, so a committed Live record survives a power loss, and a 5 s busy timeout for an older Transfer, which takes no lock. `config.json` is copied from the bundle on first launch; an unreadable one is kept as `config.json.bak` before the defaults take over.

## Window chrome

The window is an AppKit frame with SwiftUI columns, in `WindowChrome.swift`. `ChromeController` is an `NSSplitViewController` with sidebar, content, and inspector items, and it installs the `NSToolbar`: the system sidebar toggle, the back/forward group, the view-switcher group, Transfers, and an `NSSearchToolbarItem`. The columns are `SidebarColumn`, `DetailColumn`, and `InspectorColumn` in `ContentView.swift`, each hosted once and observing the model on its own. `ChromeContainer` gives the split view explicit size constraints because SwiftUI's host view does not run the constraint engine for a representable's subtree. The content item has `automaticallyAdjustsSafeAreaInsets`, so the sidebar and inspector float over a content pane that spans the whole window, and the regions they cover arrive as the pane's safe-area insets, animated with them. `BelowToolbarView` pins its hosted column to the safe-area layout guide: that starts the content and inspector columns below the toolbar, keeps the icon and list views inside the visible region, and follows the sidebar and inspector frame by frame. The sidebar runs full height. Both floating items collapse and reveal with `.useConstraints`; the holding priorities (sidebar and inspector 260, content 250) and the content pane's 260-point minimum keep the sidebar's edge fixed. The window cannot grow to make room because `ChromeContainer` pins the split to the SwiftUI-assigned size. The title bar is transparent and every separator style is `.none`; SwiftUI sets the window's separator style back to automatic once after the window appears, so `ChromeController` watches it, re-asserts none, and redraws the frame. The one line under the toolbar is `hoverLine`, drawn by hand from the content pane's visible edge to the window's right edge. It shows while the pointer is in the toolbar and for as long as the inspector is out, fading with the inspector; the pointer's position is read fresh on every refresh, never cached from enter and exit events. List view shows none, since its header has its own line. AppKit's scroll pockets over the content are hidden (see Traps); the sidebar keeps its own.

## The browser

- **Views.** List view is `ListTable`, an `NSTableView` with 22-point rows, Name always first, header sorting, per-connection column autosave, drag out, and drop onto folders. Column view is `TiledBrowser`, an `NSBrowser` with 260-point columns, inside `ColumnStack`, which keeps the browser at least as wide as its columns with its right edge on the pane's right edge, so the browser never scrolls sideways and a stack wider than the pane begins under the sidebar. Those hidden columns are reached by panning the whole stack right, with Shift and a mouse wheel or a sideways swipe (`ColumnPan`, one scroll-wheel monitor). A new or resized column slides the stack back to rest over 0.2 s. `CenteredBrowserCell` draws the icon and title on the row's midline. The coordinator answers `NSBrowser` only from the listing each column was loaded with (`shown`), reloads a column exactly when that listing changes, and rebuilds the columns after it from `ColumnTrail`; every callback that takes a row or column goes through one check first. Icon cells are `IconItemView` in a grid of fixed 108-point cells.
- **Listings.** The model keeps each folder sorted in list order and in name order (`ListingSort.merge` adds a page without a full sort) for the last 64 folders shown. A folder with no complete cached listing publishes pages at most every 80 ms; one with a cached listing keeps showing it until the new one is complete, and keeps it when the new one fails. Change events from the session relist the folders on screen. Sort column and direction persist per connection; case-insensitive names and folders first are global switches in Settings → General, as are the view mode and hidden files.
- **Keys.** `ContentKeys` is one local key monitor for Command-Down (open, as Command-O; `NSBrowser`'s column table would take it as a plain Down arrow) and Space (Quick Look). It acts only when focus is in the browser itself (the list's table, the column browser, an icon cell or the icon grid's background) or nowhere, once when held, and leaves text fields, buttons (which take Space with Full Keyboard Access), sheets, the sidebar, the inspector, and other windows alone. Quick Look is the model's `PreviewPanel`; the arrow keys move the selection behind it so it follows, as Finder's does. Escape is `Clipboard`'s own monitor: it closes an open rename bar first, then clears the clipboard. Command-F expands the toolbar search, which shows the full field when the toolbar has room and a magnifier when it does not.
- **Menus.** The icon, list, and column views share one right-click menu (`ItemMenu` in `ListTable.swift`). A right-clicked item joins the selection first, as a click would. An empty area gets the folder's menu (New Folder, Upload, Paste, Copy Remote URL) and acts on that folder: in list view it clears the selection, in column view it makes that column's folder the location, and in the icon grid it clears the selection too (`IconGridBackgroundView`). Server rows offer Connect, Edit, and Remove.
- **Drag and drop.** Drags to Finder write real files through `NSFilePromiseProvider` (`RemoteItemPromise`) and show progress in Finder. In icon view the whole cell is one drag source. Every view decides a drop with `dropAction(for:onto:model:)`, which honors remote paths only from a drag this process started and leaves the rest to `PasteRules.drop`: within a server a drag moves (one rename per item) and Option makes it copy; from another server's window it copies; from Finder it uploads. The action goes to `TransferEngine` as one shelf operation.
- **Sheets and messages.** `SheetPrompts` answers login prompts, host keys, and collisions with sheets in its window, one at a time in arrival order once no other sheet is up; each names its server or file, and one nobody answers, whose task is cancelled, or whose window closes gets the safe answer, failing its operation. A login the window moves away from takes back its sheets (`OperationPrompt.retire`), and one the user cancelled reports nothing. The model's own sheets (Delete, Go to Folder, Discard, a conflict, the connection form) never replace one on screen: a newcomer waits and shows in turn, and New Connection and Edit beep instead. Sheets about a server close when the window leaves it. Later on a conflict keeps that conflict's sheet from coming back until it is resolved; its sidebar row still opens it. Errors go to the message bar at the top of the detail column and stay until dismissed or replaced. The shelf scrolls, hears progress ten times a second, offers Stop and Restart for a transfer and Pause and Resume for a Live file, and Retry and Remove for a failure; dropped connections, timeouts, and a download whose file changed on the server retry at 1, 2, and 4 s (`RetryPolicy`). A stopped row stays stopped, never Retrying or Failed. A move that kept originals reads Kept in grey with the reason, keeps Retry and Remove, and raises no message.
- **The inspector** (Command-I) is a split column: name, kind against size, date against time, permissions against `owner:group`, then the preview. Text renders as highlighted source in a `WKWebView` with scripts off (Wrap lines is a preference); pictures are decoded off the main thread; everything else goes through `QLPreviewView`. `PreviewTiming` is the choreography: the fetch starts on the selection change, the old preview holds 100 ms so a fast fetch swaps with no animation, then the pane clears, the file's icon fades in at 500 ms, and a spinner joins it at 1 s. Opening the inspector reads differently per view: icons reflow left-packed; list's Name column gives up width; the column stack holds still while the columns fit, then slides left as one piece. `TRANSFER_ANIMATION_SCALE=6` (`open --env TRANSFER_ANIMATION_SCALE=6 …`) stretches the sidebar and inspector animations for watching them.
- **Sidebar** (Command-B): Servers, Starred, Live Files (only while one is active), Conflicts. A star's kind is learned from the server once, so a starred file is revealed, never listed. Add to Starred stars the whole selection and reads Remove from Starred when all of it is starred.
- **Tabs and windows.** New Tab (Command-T) remembers the browser window in front (`NewTab`), lets SwiftUI open the window, and joins it to that window as a tab when it appears. The join, the toolbar, and the title bar are all applied in `ChromeContainer.viewDidMoveToWindow`: SwiftUI orders the window in before it inserts the content, but nothing has drawn yet, so the tab's first frame is its finished one. A new window's sidebar starts from the server list the last window loaded. Joining logs a harmless AppKit warning that two `NSToolbarItemGroup` views were measured at zero size. Window frames follow Finder (`WindowFrames`): a new window opens at the size of the window used last, one cascade step from the front window; the last frame is kept in `transfer.windowFrame`; windows that state restoration brings back keep their own frames.
- **`sftp://` links.** `CFBundleURLTypes` claims the scheme; the app delegate hands each link to `LinkInbox`, which gives it a window showing no server (the key window first), else asks for a new tab, one window at a time, so a burst of links opens one window each. `TransferHub.connection(matching:)` picks the saved server: its saved host equal to the link's host, then its `ssh -G` host name, then the addresses that name resolves to (`SFTPURL.Match`, four `ssh -G` at a time); a user or port in the link must agree. `Tools/xfer` prints such a link on a server; it names the server from `$LC_TRANSFER_HOST`, then `~/.config/transfer/host`, then the address the ssh session arrived on, encodes every byte, and wraps the link in tmux passthrough where tmux would drop it.
- **Quit** asks Cancel or Quit Anyway (`QuitQuestion`), bringing Transfer forward first, when a Live file holds unsynced edits or a transfer has not finished in any window, closed ones included (`TransferModel.running` counts each runner for its life). It answers `.terminateLater` and awaits the Live count off the main thread; a count that does not arrive within 3 s asks too. Every master is disconnected, for at most 5 s, before the reply.

| `SessionServerTests`, `ServerTests`, `TransferServerTests`, `MoveServerTests`, `LiveRemovalServerTests`, `ThroughputServerTests` | the local sshd | Login and host keys, channels, copies, collisions, moves, Delete above Live files, relaunch, sharing and striping |
| `EditorMatrix` | the local sshd and FSEvents | Live saves the ways real editors make them: vim in every `backupcopy` mode, in-place and chunked writes, temp-and-rename, `replaceItemAt`, coordinated writes, rapid saves, touch, chmod, xattr, delete-then-recreate, a conflict |

Without a server `swift test` takes seconds and reports the server suites skipped. With one (`AGENTS.md` has the command) the full run takes about 75 s, about as long as `EditorMatrix` alone. `Scripts/local-sshd.sh [port]` starts an unprivileged `sshd` on 127.0.0.1 (port 2222 by default) with its own keys, prints its exports only once it listens, turns off `PerSourcePenalties` and raises `MaxStartups`, and removes its keys when `$TRANSFER_TEST_SSHD` is killed; it never touches Remote Login. `ServerHarness` gives each test its own library under `~/Library/Caches/TransferTests`, an ssh config passed with `-F` (never the developer's config, known hosts, or agent), and the sshd's key already known, except in the tests of the host-key questions. Each test awaits its own cleanup through `withHarness`, which runs on a throw too; a `defer { Task { … } }` cleanup never runs before the process exits. Folders there older than an hour, from a run that crashed, are removed by the next run (`TestCaches`).

TransferUI has no test target: its pure decisions live in Core (`PasteRules`, `ColumnTrail`, `ListingSort`, `QuitQuestion`, `RemotePath.typed`), and the rest is checked by hand in a packaged build.

## Still open

- A paste between servers downloads each item whole before uploading it; the two halves are not pipelined.
- Live files are not checked on the server on a timer; a remote change is seen when the copy is next saved or opened. Polling would have to flag, never refresh, since an editor may hold unsaved text.
- There is no faster engine for trees of many small files over a distant link. With channels shared, 2,000 small files at 20 ms move at about 1,600 to 2,200 files/s, but each file still costs a few round trips. The likely shape, needing nothing installed: walk and decide over SFTP as now, stream the chosen bodies with `tar` over the ssh master in batches, and place each with temp-and-rename; uploads extract into a hidden staging folder, then rename into place; any failure falls back to SFTP for what has not landed. Measure against a real server before building it.
- There is no CI: the macOS 27 SDK is not available there, and the UI is checked by hand.

## Traps

- With `-s`, the subsystem name is the command argument and must follow the destination: `ssh -S sock -s -- host sftp`. The other order asks the server for a subsystem named after the host and every channel dies at the handshake.
- OpenSSH's sftp-server reads `SSH_FXP_SYMLINK` as target then link, the reverse of the draft. The draft order creates a stray link in the server user's home directory.
- Unix socket paths are capped at 104 bytes and ssh appends 17 bytes while binding. The socket name is `ConnectionID.socketName`, twelve hex characters, not the full UUID.
- ssh splits a bare `-o Name=value` on spaces, and the library lives under `Application Support`. Paths go through `-S`, `-i`, or a double-quoted `-o` value. A bare value silently wrote a known-hosts file at `~/Library/Application`.
- FSEvents with a 0.3 s latency delivers within about 10 ms after a quiet spell, else in the next 0.3 s slot, so a delete's event can arrive after a pass that already saw the file missing. `look` must not then shorten the one-second grace for a missing copy, or an editor that deletes and recreates (about 0.8 s apart) loses its Live file. Every upload is followed by one more event on the working copy (the snapshot is an APFS clone); its stamp has not moved, so that pass does nothing.
- FSEvents reports paths, not inodes, so a safe-save needs no re-arming, but it groups events and carries flags over from earlier ones: an event only means "look again", and the flags mean nothing except the dropped-events ones, which make `LiveSync` look at every file. An in-place write is reported when the writer closes the file, possibly mid-write, which is why a pass waits for the stamp to hold still and checks it again after the snapshot. Measured with a standalone probe on macOS 27.0.
- With `automaticallyAdjustsSafeAreaInsets` on the content item, every collapse behavior but `.useConstraints` grows the content pane's frame past the window while the sidebar or inspector reveals; the pane's safe area holds still, snaps to its final size on the last frame, and the sidebar vanishes mid-animation. Collapsing is smooth under every behavior, which is why the defect only shows on open. Measured with a standalone split view on macOS 27.0.
- Under the toolbar, over each section of the window, AppKit hangs an `NSScrollPocket`, the macOS 26 scroll-edge effect. Over the content section it draws a hard edge for the placeholder screen and for the inspector column, and keeps that edge after the inspector collapses until the content changes. It stacked under `hoverLine` as a heavier line and stayed behind when the inspector left. There is no public switch (`NSScrollEdgeEffectStyle` only has automatic, soft, and hard, and `scrollEdgeEffectHidden` in SwiftUI does not reach it), so `ChromeController` hides every pocket right of the sidebar on each layout. The proof was a hierarchy dump of thin views at the toolbar's edge; the window's `titlebarSeparatorStyle` was innocent.
- AppKit gives a view no callback when only its safe-area insets change, and `layout()` is not called for that alone. A column positioned by frame math in `layout()` sat still through the whole sidebar animation. Pin to `safeAreaLayoutGuide` instead.
- `NSBrowser` scrolls its columns itself whenever its frame is narrower than they are, and that scroll cannot be driven from outside. Give it a frame at least as wide as its columns and move the frame; re-tiling columns to fit reads as a resize, not a slide.
- Column-view drag-out: the browser is also a drop target, so while its own drag crosses the browser's empty area beyond the last column, AppKit asks `validateDrop` about row −1, column −1. Answering with any operation makes `NSBrowser` (whose `pasteboardWriterForRow` path is new in macOS 27) cancel its own session and slide the icon back; the session ends 600 ms later with operation `none`, the button still down, and an end point back at the row. `validateDrop` therefore returns `[]` for column −1 whenever the pasteboard carries `remoteDragType`; Finder's drags never do, so drop-in still works. Hand paths cross that area, straight synthetic paths seldom do, which is why it looked random. Diagnose drag problems by logging `canDragRows`, `pasteboardWriterForRow`, `validateDrop` (row and column), `draggingSession:endedAt:operation:` with `NSEvent.pressedMouseButtons`, and the promise's `writePromiseTo`; AppKit reports end points in flipped screen coordinates. Spring-loading and column re-tiling were both blamed first and both proven innocent.
- Re-hosting a SwiftUI column (assigning `rootView` on every update) resets its safe-area and scroll-edge state and keeps the toolbar's edge line drawn. Host each column once and let it observe the model.
- A frame autosave name belongs to one open window; a second window that asks for it is refused and loses the name it had. SwiftUI names `WindowGroup` windows `browser-AppWindow-1`, `-2`, … and opens a new one at the scene's default size, cascaded from the front window; it rewrites `browser-AppWindow-1` when a window opens, whichever window that is. Browser windows therefore drop their autosave name, and a window's frame is watched only after it is placed. Restored windows land with no autosave name, before `applicationDidFinishLaunching`, with their own frames. Measured with the packaged app on macOS 27.0 (`open … --args -NSQuitAlwaysKeepsWindows YES` turns restoration on for one run).
- SwiftUI opens a new `WindowGroup` window for every URL the app is sent, before `application(_:open:)` runs, unless a window's content declares `.handlesExternalEvents(preferring:allowing:)`; `BrowserWindow` prefers every event, so SwiftUI opens a window only when none is open. `.handlesExternalEvents(matching: [])` on the scene instead leaves an app launched by a link with no window at all, and `newWindowForTab:` sent to the app does not open one.
- New Tab through `newWindowForTab:` alone only reached SwiftUI's window opener, which made a separate window; from `viewDidAppear` a tab showed bare and on its own first, then tabbed, then with its toolbar. Hence `NewTab` and the join in `viewDidMoveToWindow`.
- OpenSSH keeps only the first `SetEnv` line that applies to a host and ignores later ones whole, not per variable (`ssh -G -o 'SetEnv FOO=1' live` shows only `FOO`). `LC_TRANSFER_HOST` must share the line that sets `TERM`, which is why `xfer` also reads `~/.config/transfer/host`.
- `URL.resourceValues` caches per URL instance. Size and mtime for a file that changes underneath are read with `FileManager.attributesOfItem`.
- On this SDK `NSFilePromiseProvider` is an `NSPasteboardWriting` object, not an `NSItemProvider`. `RemoteItemPromise` also writes `remoteDragType` so a drop inside Transfer knows the remote paths.
- Finder's Paste ignores an `NSFilePromiseProvider` on the general pasteboard; promises work only for drags. A lazily provided `public.file-url` does not help either: the system reads a new pasteboard within about 50 ms of the write (Spotlight's clipboard history on macOS 26 and later), so the provider runs at copy time, not paste time. Hence the staging folder. Measured with a standalone probe and Finder on macOS 27.0.
- OpenSSH's `sftp-server` names the extension `copy-data`, without `@openssh.com`. The server's VERSION reply lists it; `SFTPChannel.extensions` holds that list. The reply to `copy-data` comes when the whole file is written, so it gives no byte progress and is exempt from the stall limit.
- Edit → Copy and Paste reach `ChromeController` only while something in the content holds the focus. In icon view nothing did, and after a folder opens the focused view is gone, so the first responder is a toolbar button or the window and the chain skips the controller. `IconItemView` takes the focus on click, and the app delegate, last in the chain, forwards Copy and Paste to the key window's controller (`KeyWindowEdit`). Escape reaches no single responder at all, since a focused button or window does not turn it into `cancelOperation`, so `Clipboard` watches it with a local key monitor that leaves text fields, sheets, and other windows alone.
- The icon grid's empty area is an AppKit view under the cells (`IconGridBackgroundView`), not SwiftUI gestures: a background `onTapGesture` also fired for clicks on a cell, after the cell's `mouseDown` had selected it, and cleared the selection, and a SwiftUI `dropDestination` cannot see a drag's source, so remote items could not be dropped there. Each cell's view covers its whole highlight: SwiftUI's padding around a representable hit-tests to neither the cell nor the background (measured with `hitTest` in a probe on macOS 27).
- With Full Keyboard Access on, SwiftUI gives a new bar's focus to its default button, not its field, so typing in the rename bar went nowhere and Escape reached the clipboard (measured on macOS 27). `RenameBar`'s buttons take no focus, and the field is focused again a turn after the bar appears. `NSSearchField` sends `searchFieldDidEndSearching` when backspacing empties it too; folding the field back then sent the next Return to Rename, so a field still being edited keeps its focus.
- An Objective-C exception thrown inside SwiftUI's `updateNSView` is caught by AppKit and logged, but the unwinding leaves the main thread's Observation tracking dangling, and a later read of any `@Observable` property crashes in `ObservationTracking._AccessList.addAccess`. `ColumnBrowser.Coordinator.sync` asked `parentForItems(inColumn:)` about a column that its own `reloadColumn` had just dropped. A crash in `addAccess` means look in the log for an earlier `NSInternalInconsistencyException`.
- `NSBrowser.reloadColumn` makes that column the last and drops its selection. A move out of the location's parent reloaded the parent's column, so the location's column vanished while the model still stood in it. `sync` now reads `lastColumn` on every pass and, from the first reloaded column on, selects each column from the model's trail, which brings each next column back.
- Live sync used to be spread through `SSHConnection`: two watchers per file, a settle task per file that awaited the sync, and later per-file locks. Every file event cancelled the settle task, including the event from the `(server)` download's own temp file, so a sync cancelled itself mid-download, `try?` hid it, and a cancelled `stat` read as "removed from the server": the old flaky `liveFileUploadsSavesAndSeesConflicts`. `LiveSync`'s single worker per server replaced all of it. A failed lookup is never "missing"; only `.noSuchFile` is.
- `InteractiveLane` re-ran a displaced save even when it had already finished, uploading it twice. A Live open used to ride the lane as a preview, so clicking another file while it downloaded dropped it, and every preview or neighbor prefetch restarted it from byte 0; opening a file to view had the same problem until it got the `.view` kind. Now only a newer preview interrupts a preview (`aPreviewWaitsForARunningOpen`, `finishedSaveIsNotRunAgainWhenDisplaced`).
- Renaming a Live working copy to follow its remote file stranded the editor: it kept saving to the old local name, which the watcher ignored, so those edits never uploaded. The working copy now keeps its name.
- OpenSSH 9.8 and later penalise a source address that opens connections without authenticating (`PerSourcePenalties`). A first contact with a host whose key ssh does not know makes two: the refused master and the host-key probe. Back-to-back test runs that each met a new key had the test sshd drop every connection for 15 s or more, which is why `local-sshd.sh` turns the penalty off and the harness starts with the key known. A real server keeps it, so many first logins in a short time from one address could be refused there too.
- A `ControlPersist` or `ForkAfterAuthentication` in `~/.ssh/config` forks the master into the background, where the app can neither watch nor stop it: every later login found an orphan holding the socket. The master overrides both.
