# Handoff

`PLAN.md` is the product specification. This file is the state of the code and the decisions that made it work. For window chrome, follow this file: the implementation moved past the spec’s “SwiftUI window, AppKit only at four edges.”

The package builds on Apple-silicon macOS 27 with the Xcode 27 toolchain, with no warnings. `swift test` passes. `Scripts/package-app.sh` writes `.build/Transfer.app`.

## The solution that works

Transfers ride `/usr/bin/ssh`. One ControlMaster logs in once, with `Compression=no`, and honors `~/.ssh/config`, the agent, and `ProxyJump`. SFTP is the language on the channels, spoken by this app, not by the `sftp` command. Passengers are `ssh -S sock -s -- <host> sftp` (subsystem name after the destination). Browse, interactive, and walker open at login. Data channels open on demand, at most seven, and each keeps about 2 MB of reads or writes in flight. A directory copy walks on the walker and assigns file bodies as names arrive. The fast program in `Tools/performance-version` is probed once and is still a stub, so every copy uses SFTP.

The window is an AppKit frame. `ChromeController` in `WindowChrome.swift` is an `NSSplitViewController`: a full-height sidebar, a content pane that spans the window, and an inspector. Those two float over the content, and the regions they cover are the content pane’s safe-area insets (`automaticallyAdjustsSafeAreaInsets`). `BelowToolbarView` pins each hosted column to `safeAreaLayoutGuide`, which is what keeps icon and list views under the toolbar and makes them follow the sidebar and inspector frame by frame. Both floating items collapse with `.useConstraints`. The title bar is transparent, the window separator is forced to `.none` on every layout (SwiftUI sets it back to automatic), and the one line under the toolbar is `hoverLine`, drawn by hand. AppKit’s `NSScrollPocket` views over the content are hidden; the sidebar keeps its own.

SwiftUI draws the columns (`SidebarColumn`, `DetailColumn`, `InspectorColumn`), each hosted once. List view is `ListTable`, an `NSTableView`. Column view is `TiledBrowser`, an `NSBrowser`, inside `ColumnStack`. Icon cells are `IconItemView`. Drags use `NSFilePromiseProvider` from those AppKit views.

Copy and Paste go through `Clipboard.shared` (`Clipboard.swift`), one per app, which mirrors the general pasteboard. Command-C writes the remote paths (`remoteDragType`, plus the paths as text), counts the tree on the walker, and downloads the items to a staging folder so Finder can paste them: Finder reads only file URLs from the clipboard. Paste (`PasteActions.swift`) copies on the server with `copy-data` when both ends are one server, goes through a scratch folder between servers, and uploads files copied in Finder. Option-Command-V moves: a rename on one server, else copy, compare trees with `walkTree`, then remove the source (the Trash for Finder files). The clipboard bar in `DetailColumn` shows what is held.

## Layout

| Target | Role |
| --- | --- |
| `TransferCore` | Values and decisions. No SwiftUI, AppKit, or processes. |
| `TransferIO` | `/usr/bin/ssh`, the SFTP packet codec, SQLite, Keychain, Live workspaces. |
| `TransferUI` | Windows, sheets, `NSBrowser`, file promises, Quick Look. |
| `Transfer` | `@main`. The only target that imports both UI and IO. |

Two protocols in Core are the seam. `SessionProvider` is the library: saved servers and one `RemoteSession` per server. `RemoteSession` is one server. `TransferHub` and `SSHConnection` in IO implement them. Every window has its own `TransferModel` and asks the hub for the session, so windows and tabs share one login per saved server. Views never import `TransferIO`.

`Support/config.json` lists `editableExtensions`. First launch copies it to `~/Library/Application Support/Transfer/config.json`.

## Tests

`Tests/TransferCoreTests` and `Tests/TransferIOTests/WireTests.swift` run with no network.

`Tests/TransferIOTests/EditorMatrixTests.swift` saves Live files the ways real editors do (vim in every `backupcopy` mode, in-place writes including a 5 MB chunked one, temp-and-rename, `replaceItemAt`, coordinated writes, rapid saves, touch/chmod/xattr, delete-then-recreate, a conflict) against the real FSEvents watcher and the local server, and checks that the final bytes land once, whole, with no conflict. It takes about two minutes. `Tests/TransferIOTests/ServerTests.swift` runs the real SSH master, SFTP channels, directory copy, Live sync, conflicts, and relaunch against a local server. It is skipped unless two variables are set. Start the server and run:

```bash
eval "$(Scripts/local-sshd.sh)" && swift test; kill $TRANSFER_TEST_SSHD
```

The script starts an unprivileged `sshd` on 127.0.0.1:2222 with its own keys and never touches the system's Remote Login. The tests use Trust Once, so the user's `known_hosts` is never written. Their library roots live under `~/Library/Caches/TransferTests`. Each test awaits its own cleanup through `withHarness`, which runs on a throw too; a `defer { Task { … } }` cleanup never runs before the test process exits and left hundreds of folders behind. Folders there older than an hour, from a run that crashed or was killed, are removed by the next run (`TestCaches`); younger ones may belong to a suite running now.

## Window chrome

The window is an AppKit frame with SwiftUI columns, in `Sources/TransferUI/WindowChrome.swift`. `ChromeController` is an `NSSplitViewController` with sidebar, content, and inspector items and it installs the `NSToolbar`: the system sidebar toggle, the navigational back/forward group, the view-switcher group, Transfers, and an `NSSearchToolbarItem`. The columns are `SidebarColumn`, `DetailColumn`, and `InspectorColumn` in `ContentView.swift`, each hosted once and observing the model on its own. `ChromeContainer` gives the split view explicit size constraints because SwiftUI's host view does not run the constraint engine for a representable's subtree. The content item has `automaticallyAdjustsSafeAreaInsets`, so the sidebar and inspector float over a content pane that spans the whole window, and the regions they cover arrive as the pane's safe-area insets, animated with them. `BelowToolbarView` pins its hosted column to the safe-area layout guide: that starts the content and inspector columns below the toolbar, keeps the icon and list views inside the visible region, and follows the sidebar and inspector frame by frame. The sidebar runs full height. Both floating items collapse and reveal with `.useConstraints`; the holding priorities (sidebar and inspector 260, content 250) and the content pane's 260-point minimum keep the sidebar's edge fixed. The window cannot grow to make room because `ChromeContainer` pins the split to the SwiftUI-assigned size. The title bar is transparent and every separator style is `.none`; SwiftUI sets the window's separator style back to automatic once after the window appears, so `ChromeController` watches it, re-asserts none, and redraws the frame. The one line under the toolbar is `hoverLine`, drawn by hand from the content pane's visible edge to the window's right edge. It shows while the pointer is in the toolbar and for as long as the inspector is out, fading with the inspector when that is dismissed; the pointer's position is read fresh on every refresh, never cached from enter and exit events. List view shows none, since its header has its own line. AppKit's scroll pockets over the content section are hidden (see Traps); the sidebar keeps its own.

The list view is `ListTable.swift`, an `NSTableView` with 22-point rows, header sorting, per-connection column autosave, drag out, drop onto folders, and the row context menu. The column view is `TiledBrowser`, an `NSBrowser` with 260-point columns, inside `ColumnStack`, which keeps the browser at least as wide as its columns with its right edge on the pane's right edge, so the browser never scrolls sideways and a stack wider than the pane begins under the sidebar. `CenteredBrowserCell` draws the icon and title itself so they sit on the row's midline. Both views are 22 points a row, matching Finder's column view.

## Working

- Login, askpass sheets, Keychain opt-in, one probe, browse, interactive, walker, and up to seven data channels. Each login's askpass folder and host-key probe (`ask-*`, `hostkey-*`, `key-*` under the library root) are removed on disconnect and on every failed login; what a crash or force-quit leaves is removed when the hub starts. A reserved passenger that dies is reopened once. The master's death emits `.disconnected`.
- Host keys: the offered key is learned with a no-auth `ssh` run into a temporary known-hosts file, which honors `~/.ssh/config`, aliases, and `ProxyJump`. It is compared against the files `ssh -G` reports with `ssh-keygen -F`. Always Trust and Replace write only the first user file `ssh -G` names. Trust Once keeps the temporary file for that master and deletes it on disconnect.
- Listing keeps four `READDIR` requests in flight and streams pages; the model publishes at most every 80 ms in every view and shows a cached listing first on revisit. Icon, list, and column views share one path and selection. Selecting a folder in column view makes it the current location and keeps it selected. When a listing changes under a column that is not the last (a move out of the parent, say), the browser rebuilds the columns and selection down to the location from `ColumnTrail` in TransferCore.
- Sorting: directories first and case-insensitive names are global switches in Settings > General; column and direction persist per connection. View mode and hidden files persist globally.
- Downloads and uploads keep 2 MB in flight per channel. Directory copy walks on the walker and assigns file bodies to the data pool as names arrive. Both directions use temp-and-rename, size-and-mtime skip, symlinks as links, and record temps in SQLite.
- Drag to Finder writes real files through `NSFilePromiseProvider`; a multi-item drag moves every item on an internal drop. In icon view the whole cell is one AppKit drag source (`IconItemView`), so grabbing the glyph starts the drag, not only the label. Drop on the background uploads into the current folder; drop on a folder row, in any view, uploads into that folder. A drag between folders on the same server is one SFTP rename per item.
- Column-view drag-out has one trap, found the hard way. The browser is also a drop target, so while its own drag crosses the browser's empty area beyond the last column, AppKit asks `validateDrop` about row −1, column −1. Answering with any operation makes `NSBrowser` (whose `pasteboardWriterForRow` path is new in macOS 27) cancel its own session and slide the icon back; the session ends 600 ms later with operation `none`, the button still down, and an end point back at the row. `validateDrop` therefore returns `[]` for column −1 whenever the pasteboard carries our `remoteDragType`; Finder's drags never do, so drop-in still works. Hand paths cross that area, straight synthetic paths seldom do, which is why it looked random. Diagnose drag problems by logging `canDragRows`, `pasteboardWriterForRow`, `validateDrop` (row and column), `draggingSession:endedAt:operation:` with `NSEvent.pressedMouseButtons`, and the promise's `writePromiseTo`; AppKit reports end points in flipped screen coordinates. Spring-loading and column re-tiling were both blamed first and both proven innocent.
- Live files are one component, `LiveSync` (`LiveSync.swift`), owned by the hub: the records and their `live_files` rows (dirty, paused, the conflict and what the server held, the working copy's exact stamp and SHA-256 at the last sync), one FSEvents stream over the Live folder (`LiveWatcher`), and one worker per server. Every pass and every command for a server's files (open, conflict choices, discard, and a rename or delete under a Live path) runs on that worker in turn, so nothing races and nothing is locked. A rename or delete also waits on the worker when a Live open under that path is still queued or downloading, since its record does not exist yet (`renameWaitsForAnOpenInFlight`). A rename changes only the remote path: the working copy keeps its old local name, because an editor holding it open keeps saving there and the watcher knows the copy only by that name. The cost is cosmetic: the editor's title and the Live folder show the old name, and the `(server)` copy is named after the working copy. A pass acts only on a working copy that has held still for 350 ms, then asks `LiveDecision` in TransferCore what to do, feeding it a digest when the stamp moved and the server's file when the copy changed: touched-only copies are restamped, not uploaded; a copy missing once gets a second look a second later; an unreachable server parks the pass until login; retries are scheduled at 1, 2, and 4 s, not slept. A Live open downloads on the interactive lane as `.open`: a preview displaces it but never drops it, and it runs again after that preview (`openDisplacedByAPreviewStillCompletes`); previews still replace each other. Uploads read through `NSFileCoordinator`, go on the interactive lane, and check just before the rename that the server still holds the base (or this save's own bytes); the new base is our own temp's fingerprint. A conflict writes the `(server)` copy first, then sets the flag and sends the event together. Keep Local expects the server file seen when the conflict was raised, so an edit made after that is not overwritten. An untouched copy is refreshed from the server only when the user opens it again, never behind an open editor. `SSHConnection` is the `LiveServer` (look up, fetch, save with an expectation, list names, emit) and forwards the public Live API. Compare opens `opendiff` from IO. Keep Local and Keep Remote need a second press.
- Shelf rows offer Pause, Resume, Retry, and Remove. Dropped connections and timeouts retry at 1 s, 2 s, and 4 s. Live uploads can be paused too.
- Command-Down opens the selection, as Command-O does (a folder navigates). It has no menu item: `OpenShortcut` in `WindowChrome.swift` is one local key monitor, since `NSBrowser`'s column table takes Command-Down as a plain Down arrow before the browser's `keyDown` sees it (as does `NSTableView`). It acts only for the content pane (or a window with nothing focused), fires once when held, and leaves text fields, sheets, the sidebar, the inspector, and other windows alone. Command-Up stays Go > Parent.
- Window frames follow Finder (`WindowFrames` in `WindowChrome.swift`). A new window opens at the size of the window used last, one cascade step from the front window, or at the last window's frame when it is the only one; the frame of the last window moved, resized, or made main is kept in `transfer.windowFrame`. Windows that state restoration brings back (they land before `applicationDidFinishLaunching`) keep their own frames, so every window's frame survives a relaunch when windows are restored. Browser windows drop their frame autosave name. A window's frame is watched only after it is placed: it becomes main at SwiftUI's default size first, which would otherwise replace the last-used frame.
- Command-F expands the toolbar search. The search item shows the full field when the toolbar has room and a magnifier when it does not, as Finder's does. Space and Return leave text fields alone.
- Settings (Command-Comma) has General, Extensions, and Updates tabs. Extensions edits `config.json` through the provider; open sessions pick the list up at once.
- Preview cache names are SHA256 of the raw path, capped at 1 GB by last use, excluded from backup. `prepareViewFile` returns the cached copy without a download when its size and mtime match the remote file.
- The inspector (Command-Shift-I) is a split column: bold name, kind against size, a divider, date against time, permissions against `owner:group`, then the preview. Text files render as highlighted, wrapped-or-not source in a `WKWebView` (the `Wrap lines` checkbox is a preference); pictures are decoded off the main thread; everything else goes through `QLPreviewView`. `PreviewTiming` in `TransferModel.swift` is the choreography: the fetch starts on the selection change, the old preview holds 100 ms so a fast fetch swaps with no animation, then the pane clears, the file icon fades in at 500 ms, a spinner joins it at 1 s. After each preview the files on either side are prefetched one at a time. Sizes everywhere use `Units.scale`, three characters plus an SI prefix.
- Opening the inspector reads differently per view. Icon: the grid reflows narrower, items left-packed at a fixed 108-point cell so nothing shimmies; long names wrap to two lines and middle-truncate. List: the Name column gives up width and the others hold, with a horizontal scroller only when the window is too narrow. Column: the stack holds still while the columns fit, and once the inspector's edge reaches the deepest column the whole stack slides left as one piece, the deepest column abutting the inspector and the first disappearing under the glass sidebar; closing reverses it, and the sidebar's edge never moves. A column that appears or is resized while the pane is at rest slides the stack over 0.2 s, as Finder's does. `TRANSFER_ANIMATION_SCALE=6` in the environment (`open --env TRANSFER_ANIMATION_SCALE=6 .build/Transfer.app`) stretches the sidebar and inspector animations for watching them.
- Quick Look opens on Space in every view (`togglePreview`), through `keyDown` on the table and the browser and `onKeyPress(.space)` on the icon grid; the model's `PreviewPanel` handles the panel. Space or Escape inside the panel closes it, and the arrow keys move the selection behind it so the panel follows, as Finder's does.
- Sidebar: Servers, Starred, Live Files (only while active), Conflicts. Starred holds files and folders; a star's kind is learned from the server once so a starred file is revealed, never listed. Server rows offer Connect, Edit, and Remove. Remove refuses while that server has unsynced Live bytes.
- Copy and Paste of files and folders, in every view: inside a server, between servers, windows, and tabs, and with Finder both ways. Command-C, Command-V, Option-Command-V (Move Item Here), Escape clears; Copy Remote URL moved to Option-Command-C. Pasting into the source folder makes `name copy`; a folder into itself is refused, except that in column view a copied folder that is still the selected location pastes beside itself. The bar reads "Copied 3 files and 1 folder (31 files in all, 12 MB)", with the source and Finder readiness below. Server-side copy keeps mode and mtime, so a second paste of the same tree is skipped file by file. Copies over 1 GB are not staged for Finder. Staging and the scratch folders live under `~/Library/Caches/<bundle id>/` and are removed at quit and launch; quitting also clears a clipboard that points into them.
- Quit asks Cancel or Quit Anyway through the app delegate whenever any server has unsynced Live work, and disconnects every master on the way out.

## Updates

Sparkle 2 is a SwiftPM dependency of the app target. `Scripts/package-app.sh` copies the framework into the bundle, adds the rpath, and signs the inner pieces before the app. `Check for Updates…` sits in the app menu. The updater starts only when `SUPublicEDKey` in `Support/Info.plist` is non-empty, so a build without a key runs quietly.

To turn updates on: run `.build/artifacts/sparkle/Sparkle/bin/generate_keys` once, which keeps the private key in the login keychain and prints the public key; paste that into `SUPublicEDKey`. Each release is a zip of the signed, notarized app plus `appcast.xml` from `bin/generate_appcast`, attached to a GitHub release. The feed URL points at the latest release's `appcast.xml`. Ad-hoc signed builds cannot install an update over themselves; that needs Developer ID via `SIGN="Developer ID Application: …" Scripts/package-app.sh`.

## Still open

- Small files do not share a data channel; every file takes a channel from the pool of seven.
- New Tab (Command-T) opens a separate window, not a tab: `newWindowForTab:` reaches SwiftUI, which opens a scene window, and the new window's `tabbingMode = .preferred` is set only after it is on screen.
- The fast directory engine stays unwired. `PerformanceDirectoryCopy.available()` returns false.
- A paste between servers downloads the whole item before uploading it; the two halves are not pipelined.
- Live files are not checked on the server on a timer; a remote change is seen when the copy is next saved or opened. Polling would have to flag, never refresh, since an editor may hold unsaved text.

## Traps

- With `-s`, the subsystem name is the command argument and must follow the destination: `ssh -S sock -s -- host sftp`. The other order asks the server for a subsystem named after the host and every channel dies at the handshake. `PLAN.md` §3 was corrected.
- OpenSSH's sftp-server reads `SSH_FXP_SYMLINK` as target then link, the reverse of the draft. The draft order creates a stray link in the server user's home directory.
- Unix socket paths are capped at 104 bytes and ssh appends 17 bytes while binding. The socket name is `ConnectionID.socketName`, twelve hex characters, not the full UUID.
- ssh splits a bare `-o Name=value` on spaces, and the library lives under `Application Support`. Paths go through `-S`, `-i`, or a double-quoted `-o` value. A bare value silently wrote a known-hosts file at `~/Library/Application`.
- FSEvents with a 0.3 s latency delivers within about 10 ms after a quiet spell, else in the next 0.3 s slot, so a delete's event can arrive after a pass that already saw the file missing. `look` must not then shorten the one-second grace for a missing copy, or an editor that deletes and recreates (about 0.8 s apart) loses its Live file. Every upload is followed by one more event on the working copy (the snapshot is an APFS clone); that pass does nothing.
- FSEvents reports paths, not inodes, so a safe-save needs no re-arming, but it groups events and carries flags over from earlier ones: an event only means "look again", and the flags mean nothing except the dropped-events ones, which make `LiveSync` look at every file. An in-place write is reported when the writer closes the file, possibly mid-write, which is why a pass waits for the stamp to hold still and checks it again after the snapshot. Measured with a standalone probe on macOS 27.0.
- With `automaticallyAdjustsSafeAreaInsets` on the content item, every collapse behavior but `.useConstraints` grows the content pane's frame past the window while the sidebar or inspector reveals; the pane's safe area holds still, snaps to its final size on the last frame, and the sidebar vanishes mid-animation. Collapsing is smooth under every behavior, which is why the defect only shows on open. Measured with a standalone split view on macOS 27.0.
- Under the toolbar, over each section of the window, AppKit hangs an `NSScrollPocket`, the macOS 26 scroll-edge effect. Over the content section it draws a hard edge for the placeholder screen and for the inspector column, and keeps that edge after the inspector collapses until the content changes. It stacked under `hoverLine` as a heavier line and stayed behind when the inspector left. There is no public switch (`NSScrollEdgeEffectStyle` only has automatic, soft, and hard, and `scrollEdgeEffectHidden` in SwiftUI does not reach it), so `ChromeController` hides every pocket right of the sidebar on each layout. The proof was a hierarchy dump of thin views at the toolbar's edge; the window's `titlebarSeparatorStyle` was innocent.
- AppKit gives a view no callback when only its safe-area insets change, and `layout()` is not called for that alone. A column positioned by frame math in `layout()` sat still through the whole sidebar animation. Pin to `safeAreaLayoutGuide` instead.
- `NSBrowser` scrolls its columns itself whenever its frame is narrower than they are, and that scroll cannot be driven from outside. Give it a frame at least as wide as its columns and move the frame; re-tiling columns to fit reads as a resize, not a slide.
- Re-hosting a SwiftUI column (assigning `rootView` on every update) resets its safe-area and scroll-edge state and keeps the toolbar's edge line drawn. Host each column once and let it observe the model.
- A frame autosave name belongs to one open window; a second window that asks for it is refused and loses the name it had. SwiftUI names `WindowGroup` windows `browser-AppWindow-1`, `-2`, … and opens a new one at the scene's default size, cascaded from the front window; it rewrites `browser-AppWindow-1` when a window opens, whichever window that is. Restored windows land with no autosave name, before `applicationDidFinishLaunching`, with their own frames. Measured with the packaged app on macOS 27.0 (`open … --args -NSQuitAlwaysKeepsWindows YES` turns restoration on for one run).
- `URL.resourceValues` caches per URL instance. Size and mtime for a file that changes underneath are read with `FileManager.attributesOfItem`.
- On this SDK `NSFilePromiseProvider` is an `NSPasteboardWriting` object, not an `NSItemProvider`. `RemoteItemPromise` also writes `com.example.transfer.remote-items` so a drop inside Transfer knows the remote paths.
- Finder's Paste ignores an `NSFilePromiseProvider` on the general pasteboard; promises work only for drags. A lazily provided `public.file-url` does not help either: the system reads a new pasteboard within about 50 ms of the write (Spotlight's clipboard history on macOS 26 and later), so the provider runs at copy time, not paste time. Hence the staging folder. Measured with a standalone probe and Finder on macOS 27.0.
- OpenSSH's `sftp-server` names the extension `copy-data`, without `@openssh.com`. The server's VERSION reply lists it; `SFTPLink.extensions` holds that list. The reply to `copy-data` comes when the whole file is written, so it gives no byte progress.
- Edit > Copy and Paste reach `ChromeController` only while something in the content holds the focus. In icon view nothing did, and after a folder opens the focused view is gone, so the first responder is a toolbar button or the window and the chain skips the controller. `IconItemView` takes the focus on click, and the app delegate, last in the chain, forwards Copy and Paste to the key window's controller (`KeyWindowEdit`). Escape reaches no single responder at all, since a focused button or window does not turn it into `cancelOperation`, so `Clipboard` watches it with a local key monitor that leaves text fields, sheets, and other windows alone.
- The icon grid's background `onTapGesture` also fires for clicks on a cell, after the cell's `mouseDown` has selected it, and cleared the selection. `IconItemView` records `model.itemClickTime`, and the tap leaves the selection alone within half a second of it.
- An Objective-C exception thrown inside SwiftUI's `updateNSView` is caught by AppKit and logged, but the unwinding leaves the main thread's Observation tracking dangling, and a later read of any `@Observable` property crashes in `ObservationTracking._AccessList.addAccess`. `ColumnBrowser.Coordinator.sync` asked `parentForItems(inColumn:)` about a column that its own `reloadColumn` had just dropped. A crash in `addAccess` means look in the log for an earlier `NSInternalInconsistencyException`.
- `NSBrowser.reloadColumn` makes that column the last and drops its selection. A move out of the location's parent reloaded the parent's column, so the location's column vanished while the model still stood in it. `ColumnBrowser.Coordinator.sync` now trims to the reloaded column itself and selects each column from there on from the model's trail, which brings each next column back.
- Live sync used to be spread through `SSHConnection`: two watchers per file, a settle task per file that awaited the sync, and later per-file locks. Every file event cancelled the settle task, including the event from the `(server)` download's own temp file, so a sync cancelled itself mid-download, `try?` hid it, and a cancelled `stat` read as "removed from the server": the old flaky `liveFileUploadsSavesAndSeesConflicts`. `LiveSync`'s single worker per server replaced all of it. A failed lookup is never "missing"; only `.noSuchFile` is.
- `InteractiveLane` re-ran a displaced save even when it had already finished, uploading it twice. A Live open used to ride the lane as a preview, so clicking another file while it downloaded dropped it with `cancelled`, and once re-queued, every preview or neighbor prefetch restarted it from byte 0. Now only a preview is ever interrupted, by a newer preview; a Live open or save runs to the end and a preview waits behind it (`aPreviewWaitsForARunningOpen`, `finishedSaveIsNotRunAgainWhenDisplaced`).
- Renaming a Live working copy to follow its remote file stranded the editor: it kept saving to the old local name, which the watcher ignored, so those edits never uploaded. The working copy now keeps its name.
- OpenSSH 9.8 and later penalise a source address that opens connections without authenticating (`PerSourcePenalties`). Every login's host-key probe is one, so back-to-back test runs had the test sshd drop every connection for 15 s or more. `Scripts/local-sshd.sh` turns the penalty off; a real server keeps it, and many logins in a short time from one address could be refused there too.
- When the server advertises `posix-rename@openssh.com`, `SFTPLink.replace` never removes the destination before renaming onto it; a failed rename leaves the old file in place.
- Do not add libssh, a tunnel, HTTP/3, or compression. The transport is `/usr/bin/ssh`.
- Do not embed rsync. A later fast copy replaces `Tools/performance-version` and must not change the browser.
